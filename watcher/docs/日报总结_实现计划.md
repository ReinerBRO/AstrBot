> 创建日期：2026-02-12
> 状态：📋 待开发

## 1. 功能概述

基于每日活动记录（`reports/YYYY-MM-DD.md`），自动生成结构化的日报总结，包含统计数据、时间段分析和 LLM 生成的自然语言总结。

### 1.1 用户场景
- 用户选择日期 → 点击"生成日报" → 查看当天活动总结
- 已生成的日报缓存到本地，避免重复调用 LLM
- 支持重新生成（覆盖缓存）

### 1.2 总结内容
1. **统计概览**：总条目数、活跃时长、时间范围、分类分布
2. **时间段分析**：将一天切分为若干活动段，每段标注主要活动
3. **自然语言总结**：LLM 生成的一段话概括当天工作
4. **亮点提取**：3-5 条关键活动摘要

## 2. 数据结构

### 2.1 日报总结 JSON（缓存文件：`reports/YYYY-MM-DD.summary.json`）

```json
{
  "date": "2026-02-11",
  "generated_at": "2026-02-11T23:30:00",
  "stats": {
    "total_entries": 47,
    "time_range": { "start": "00:41", "end": "22:59" },
    "active_duration_min": 510,
    "categories": {
      "写代码": { "count": 16, "percentage": 34, "duration_min": 180 },
      "研究": { "count": 14, "percentage": 30, "duration_min": 150 },
      "娱乐": { "count": 17, "percentage": 36, "duration_min": 180 }
    }
  },
  "timeline_segments": [
    {
      "start": "00:41",
      "end": "00:51",
      "main_category": "研究",
      "description": "研究多头注意力机制，查看项目配置"
    },
    {
      "start": "10:31",
      "end": "11:47",
      "main_category": "写代码",
      "description": "开发LLM事件分类器，调试代码和测试"
    }
  ],
  "summary": "今天主要围绕Watcher项目进行开发工作，上午集中编写和调试LLM事件分类器...",
  "highlights": [
    "编写和调试LLM事件分类器代码",
    "在LeetCode上练习算法题",
    "阅读《剑风传奇》漫画"
  ]
}
```

### 2.2 API 响应格式

`GET /api/daily-summary?date=2026-02-11` 返回上述 JSON。

`POST /api/daily-summary/generate` 请求体：
```json
{
  "date": "2026-02-11",
  "force": false
}
```
- `force=true`：强制重新生成（忽略缓存）
- `force=false`：有缓存则直接返回

## 3. Agent 分工

### 3.1 Agent A — 后端

#### 任务清单

**3.1.1 报告解析器（`watcher/report_parser.py` 新建）**
- `parse_daily_report(date_str: str, report_dir: str) -> list[ReportEntry]`
  - 解析 `reports/YYYY-MM-DD.md`，提取每条记录的 time、category、tree_id、summary
- `ReportEntry` 数据类：`time`, `category`, `tree_id`, `summary`, `source`, `meta`

**3.1.2 统计聚合器（`watcher/daily_summary.py` 新建）**
- `aggregate_stats(entries: list[ReportEntry]) -> DailyStats`
  - 总条目数、时间范围、活跃时长
  - 分类分布（count、percentage、估算 duration）
  - duration 估算逻辑：相邻条目时间差，最后一条默认 5 分钟
- `build_timeline_segments(entries: list[ReportEntry]) -> list[TimelineSegment]`
  - 连续相同分类的条目合并为一个时间段
  - 间隔 > 30 分钟视为新段

**3.1.3 LLM 总结生成（`watcher/daily_summary.py`）**
- `generate_llm_summary(entries: list[ReportEntry], stats: DailyStats, config: Config) -> SummaryResult`
  - 构造 prompt：传入统计数据 + 条目列表
  - 调用 `_chat_openai`（复用 `api_client.py` 的模式）
  - 返回：summary（一段话）+ highlights（3-5 条）
  - 使用 `DAILY_SUMMARY_MODEL` 配置项（默认 fallback 到 `LLM_MODEL`）
- prompt 设计：
  ```
  你是工作日志助手。请根据以下一天的活动记录生成日报总结。
  要求：
  1. summary：用 2-3 句话概括今天的主要工作和活动
  2. highlights：提取 3-5 条关键活动亮点
  输出 JSON：{"summary": "...", "highlights": ["...", "..."]}
  ```

**3.1.4 缓存管理**
- 生成后保存到 `reports/YYYY-MM-DD.summary.json`
- 读取时优先检查缓存文件
- `force=true` 时跳过缓存

**3.1.5 Service 层（`app/service.py` 修改）**
- `daily_summary(date_str: str, force: bool = False) -> dict`
  - 检查缓存 → 解析报告 → 聚合统计 → 调用 LLM → 保存缓存 → 返回

**3.1.6 API 路由（`app/web.py` 修改）**
- `GET /api/daily-summary?date=YYYY-MM-DD` — 获取日报（有缓存直接返回）
- `POST /api/daily-summary/generate` — 生成/重新生成日报

**3.1.7 配置项（`watcher/config.py` 修改）**
- `DAILY_SUMMARY_MODEL`：日报总结使用的模型（默认 `LLM_MODEL`）
- `DAILY_SUMMARY_MAX_TOKENS`：最大 token 数（默认 1024）

**3.1.8 测试**
- `tests/test_report_parser.py`：解析器单元测试（正常/空/异常格式）
- `tests/test_daily_summary.py`：聚合 + timeline 分段测试
- 覆盖率目标：80%+

## 4. 接口约定

### 4.1 Agent A 提供给 Agent B 的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/daily-summary?date=YYYY-MM-DD` | 获取日报（有缓存直接返回，无缓存返回 404） |
| POST | `/api/daily-summary/generate` | 生成日报，body: `{date, force}` |

### 4.2 响应格式

**成功（200）**：
```json
{
  "date": "2026-02-11",
  "generated_at": "...",
  "stats": { ... },
  "timeline_segments": [ ... ],
  "summary": "...",
  "highlights": [ ... ]
}
```

**无数据（404）**：
```json
{ "error": "no_data", "message": "该日期无活动记录" }
```

**生成中（202）**：（如果后续需要异步）
```json
{ "status": "generating" }
```

## 7. 注意事项

1. **成本控制**：LLM 调用仅在用户主动点击"生成"时触发，不自动生成
2. **缓存优先**：已生成的日报直接读缓存，不重复调用 LLM
3. **降级方案**：LLM 不可用时，仅返回统计数据和时间段（无 summary/highlights）
4. **隐私**：summary.json 与 report.md 同目录，遵循相同的 gitignore 规则
5. **模型兼容**：使用 OpenAI 兼容格式（`_chat_openai`），支持任意兼容 API
