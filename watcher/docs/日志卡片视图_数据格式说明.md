# 日志卡片视图数据格式说明

更新时间：2026-02-11

## 1. 报告行原始格式

卡片数据来源于 `reports/YYYY-MM-DD.md`，单行格式：

```text
- HH:MM [分类] {tree:树ID} 摘要文本 (source=...; vl=...; event=...; reason=...)
```

说明：

- `{tree:...}` 可选
- `(...source=...)` 元信息可选（当前写入逻辑仅在 `source != vl` 时追加）

## 2. card_id 规则

- 格式：`YYYYMMDD-HHMM-序号`
- 示例：`20260211-0941-001`
- 序号为当日报告文件中可解析卡片的 1-based 顺序号（3~6 位零填充）

## 3. Card 对象字段

```json
{
  "id": "20260211-0941-001",
  "time": "09:41",
  "date": "2026-02-11",
  "category": "写代码",
  "summary": "正在启动工作追踪系统",
  "tree_id": "tree-abc",
  "tree_name": "Morning Tree",
  "source": "vl+event",
  "confidence": 0.62,
  "vl_category": "写代码",
  "event_category": "研究",
  "event_data": {
    "click_count": 0,
    "top_app": "",
    "active_seconds": 0
  }
}
```

字段含义：

- `source`：`vl` / `event` / `vl+event`（`fusion` 在卡片层映射为 `vl+event`）
- `confidence`：从元信息解析，优先显式 `confidence=`；否则尝试从 `reason` 中提取 0~1 小数；无则 `0.0`
- `tree_name`：优先读取 `.trees.json`；缺失时回退到当日推断树名
- `event_data`：当前后端固定占位（后续可对接真实事件统计）

## 4. stats 结构

```json
{
  "total_count": 42,
  "category_counts": {
    "写代码": 18,
    "研究": 15,
    "娱乐": 9
  },
  "total_active_seconds": 23400,
  "avg_interval_seconds": 558,
  "date_range": {
    "start": "2026-02-07",
    "end": "2026-02-11"
  }
}
```

规则：

- `category_counts`：按筛选后的卡片聚合
- `total_active_seconds`：相邻卡片时间差累加，单段上限 3600 秒
- `avg_interval_seconds`：相邻时间差平均值（整数）
- `date_range`：当前查询范围内的实际起止日期

## 5. 导出格式

- Markdown：按卡片行输出，保留核心字段与元信息
- JSON：`{"cards":[...], "stats":{...}}`
- CSV：固定列
  - `id,date,time,category,summary,tree_id,tree_name,source,confidence,vl_category,event_category`
