## 1. 背景与目标

### 1.1 现状问题
当前树视图是装饰性的"生长树"：一根主干 + 按分类泳道散列的果实。所有条目平铺排列，没有逻辑层级关系。

### 1.2 目标
实现真正的逻辑树：
- 主干代表时间主线
- 分类切换时产生分支（如：写代码 → 研究 = 分叉点）
- 同一分类的连续活动沿同一分支生长
- 长时间间隔（>30min）产生新的主分支
- 回到之前的分类时，从主干再次分叉（而非合并回旧分支）

### 1.3 视觉效果
```

          ├─ 22:18 研究 (LeetCode题目)
     ┌────┤

     │         ├─ 21:36 漫画
     │         └─ 21:08 红包页面
     │
```

## 2. 核心算法

### 2.1 树构建算法（后端）

**输入**：`list[ReportEntry]`（按时间排序的活动记录）
**输出**：`TreeNode`（树形结构）

```
TreeNode:
  id: str
  time_start: str          # 分支起始时间
  time_end: str            # 分支结束时间
  category: str | None     # 分支主分类（None = 主干）
  entries: list[Entry]     # 该分支上的叶子节点
  children: list[TreeNode] # 子分支
```

**分支规则**：
1. 按时间顺序遍历条目
2. 连续相同分类的条目归入同一分支
3. 分类切换 → 当前分支结束，新分支从主干分叉
4. 时间间隔 > 30 分钟 → 强制新的主分支段（即使分类相同）
5. 主干段（trunk segment）：包含多个子分支的容器

**伪代码**：
```python
def build_logical_tree(entries):
    root = TreeNode(id="root", category=None)
    current_trunk_segment = TreeNode(id="seg-0", category=None)
    root.children.append(current_trunk_segment)

    current_branch = None
    prev_entry = None

    for entry in sorted_entries:
        gap = time_gap(prev_entry, entry)

        # 长间隔 → 新主干段
        if gap > 30:
            current_trunk_segment = TreeNode(id=new_id(), category=None)
            root.children.append(current_trunk_segment)
            current_branch = None

        # 分类切换 → 新分支
        if current_branch is None or entry.category != current_branch.category:
            current_branch = TreeNode(
                id=new_id(),
                category=entry.category,
                time_start=entry.time,
            )
            current_trunk_segment.children.append(current_branch)

        current_branch.entries.append(entry)
        current_branch.time_end = entry.time
        prev_entry = entry

    return root
```

### 2.2 布局算法（前端）

**输入**：`TreeNode`（树形 JSON）
**输出**：每个节点的 `(x, y)` 坐标

**布局策略**：
- 主干垂直居中，从下往上生长
- 子分支交替向左右延伸
- 分支长度与条目数量成正比
- 叶子节点沿分支等距排列
- 分支角度：30°-60°，避免重叠

**碰撞检测**：
- 分支分配左右方向时，检查是否与已有分支重叠
- 重叠时调整角度或偏移

## 3. Agent 分工

### 3.1 Agent A — 后端（树构建算法 + API）

#### 任务清单

**3.1.1 树构建模块（`watcher/tree_builder.py` 新建）**

数据类：
```python
@dataclass
class TreeEntry:
    time: str
    category: str
    summary: str
    source: str

@dataclass
class BranchNode:
    id: str
    category: str | None        # None = 主干段
    time_start: str | None
    time_end: str | None
    entries: list[TreeEntry]
    children: list["BranchNode"]
    depth: int                   # 0=root, 1=trunk_segment, 2=branch
```

核心函数：
- `build_logical_tree(entries: list[ReportEntry], gap_threshold: int = 30) -> BranchNode`
  - 实现 §2.1 的分支规则
  - 返回树形结构
- `tree_to_dict(node: BranchNode) -> dict`
  - 序列化为 JSON 可传输的 dict
- `compute_tree_stats(node: BranchNode) -> dict`
  - 统计：总分支数、最深层级、各分类分支数、最长分支

**3.1.2 API 集成（`app/service.py` 修改）**
- `tree_data()` 返回值新增 `logical_tree` 字段
- 调用 `build_logical_tree()` 构建逻辑树
- 与现有 `entries` 并行返回（向后兼容）

**3.1.3 配置项（`watcher/config.py` 修改）**
- `TREE_GAP_THRESHOLD_MIN`：分支间隔阈值（默认 30 分钟）
- `TREE_LAYOUT_MODE`：布局模式（`logical` | `classic`，默认 `logical`）

**3.1.4 测试（`tests/test_tree_builder.py` 新建）**
- 空输入 → 空树
- 单分类连续 → 单分支
- 分类切换 → 多分支
- 长间隔 → 新主干段
- 混合场景（真实数据模拟）
- 覆盖率目标：85%+

### 3.2 Agent B — 前端（逻辑树布局 + 渲染）

#### 任务清单

**3.2.1 逻辑树布局引擎（`app.js` 修改）**

新增函数：
- `buildLogicalLayout(logicalTree, metrics, width, height)` → 布局结果
  - 递归遍历树结构
  - 主干段垂直排列
  - 子分支交替左右分配
  - 计算每个节点的 `(x, y)` 坐标
  - 返回：`{ trunk, branches, nodes }` 布局数据

- `assignBranchDirections(trunkSegment, existingBranches)` → 分支方向
  - 交替左右分配
  - 同一分类尽量保持同侧
  - 碰撞检测与调整

- `layoutBranchNodes(branch, startX, startY, direction, angle)` → 节点坐标
  - 沿分支方向等距排列叶子节点
  - 分支长度 = 条目数 × 节点间距

**3.2.2 逻辑树渲染（`app.js` 修改）**

修改 `buildTreeScene` 和渲染函数：
- 检测 `data.logical_tree` 是否存在
  - 存在 → 使用逻辑树布局
  - 不存在 → 回退到经典布局（向后兼容）

新增渲染函数：
- `drawLogicalTrunk(ctx, scene)` — 绘制主干（分段，每段之间有间隔标注）
- `drawLogicalBranch(ctx, branch)` — 绘制分支（贝塞尔曲线，从主干分叉）
- `drawBranchLabel(ctx, branch)` — 分支标签（分类名 + 时间范围）
- `drawLogicalNode(ctx, node)` — 叶子节点（圆形 + 时间标签）
- `drawBranchConnector(ctx, parentNode, childBranch)` — 分叉连接线

**3.2.3 视觉设计**
- 主干：粗线（8-10px），深色，垂直居中
- 分支：中等粗细（4-6px），分类颜色，贝塞尔曲线

**3.2.4 交互**

## 6. 注意事项

1. **向后兼容**：`logical_tree` 是新增字段，不影响现有 `entries` 和经典布局
2. **性能**：树构建是 O(n) 遍历，不会影响 API 响应时间
3. **大数据量**：超过 100 个条目时，深层分支可默认折叠
4. **动画一致性**：逻辑树的生长动画应与现有树视图风格一致（贝塞尔曲线、渐进展开）
5. **分支方向**：同一分类尽量保持同侧，减少视觉混乱
