# Showcase Demo Playbook

This document provides two practical assets for all five showcase versions:

- a two-minute demo script
- a demo acceptance checklist

The goal is strict:

- the audience must see the difference
- the audience must hear the difference
- the group must have a stable script for meetings

## Global Demo Rules

Use the same user identity across all versions.

Recommended demo persona:

- role: graduate student
- topic: personalized AI agent research
- preferences: prefers structured planning, paper recommendations, and minimal interruptions

Keep one stable user story across all versions:

`I am building a personalized AI agent for research and productivity.`

Every version demo should contain:

1. one sentence for the version upgrade
2. one visible UI change
3. one new user interaction
4. one behavior that the previous version could not do

## V1 Demo Script

### Version Theme

Integrated PoC

### Whole-Group Upgrade Line

`Compared with the original base system, V1 now gives us a unified Personalized AI Agent product shell.`

### Two-Minute Demo Script

#### 0:00-0:20 Opening

`This is V1, our integrated proof of concept. The main change is that the system is no longer presented as a generic chatbot. It is now framed as a Personalized AI Agent product with explicit modules and user modes.`

#### 0:20-0:45 Show the Entry

Actions:

- open the homepage
- show the new project branding
- point to the sidebar
- point to the mode switcher

Say:

`The first visible improvement is the product shell. We now have dedicated entry points for profile, memory, recommendation, workflow, and trust.`

#### 0:45-1:15 Create the Profile

Actions:

- open profile panel
- enter research goal
- enter preference such as structured planning
- save

Say:

`The second change is that the system starts from a user profile instead of anonymous chat. This creates the foundation for personalization.`

#### 1:15-1:40 Run the First Chat

Actions:

- switch to Mentor mode
- ask: `Help me start a personalized AI agent project.`

Say:

`The third change is that we now expose multiple agent modes. Even in this first version, the user can choose different high-level interaction styles.`

#### 1:40-2:00 Close

Actions:

- show the module pages in the navigation

Say:

`So the key result of V1 is not depth yet, but product integration. We now have a visible shell where all six modules can evolve in later versions.`

### Acceptance Checklist

- the homepage looks different from the original Persbot shell
- the sidebar contains explicit module entry points
- the profile panel can be opened and saved
- the mode switcher is visible and usable
- the presenter can clearly say that V1 is about productization, not deep intelligence yet

## V2 Demo Script

### Version Theme

Memory Growth

### Whole-Group Upgrade Line

`Compared with V1, V2 now remembers past sessions and exposes memory as a visible system capability.`

### Two-Minute Demo Script

#### 0:00-0:20 Opening

`This is V2. The key difference from V1 is that the system is no longer only personalized by static profile. It now retains and recalls user context across sessions.`

#### 0:20-0:45 Show the Memory Page

Actions:

- open Memory page
- show memory timeline
- show semantic summary

Say:

`The first visible difference is the dedicated memory interface. We can now inspect episodic history and a higher-level semantic summary.`

#### 0:45-1:15 Demonstrate Recall

Actions:

- start a fresh session
- ask: `What do you remember about my project preferences?`

Say:

`The key behavioral upgrade is cross-session recall. The system should remember that I care about personalized AI agent research and structured planning.`

#### 1:15-1:40 Show Memory Attribution

Actions:

- point to the recalled memory tags or summary references
- optionally edit or delete a memory item

Say:

`Unlike V1, V2 also makes memory inspectable and correctable. This is important because personalization must remain visible and editable.`

#### 1:40-2:00 Close

Say:

`So V2 upgrades the shell into a memory-aware agent. The system now has persistent context, visible memory structure, and a user correction path.`

### Acceptance Checklist

- a dedicated memory page exists
- memory timeline is visible
- semantic summary is visible
- a new session can recall a prior fact or preference
- at least one memory item can be edited, hidden, or deleted
- the presenter can clearly state that V2 adds cross-session memory

## V3 Demo Script

### Version Theme

Mentor Loop

### Whole-Group Upgrade Line

`Compared with V2, V3 now gives proactive guidance instead of only remembering and answering.`

### Two-Minute Demo Script

#### 0:00-0:20 Opening

`This is V3. The major change is that the system now behaves like a mentor. It does not only recall user context, but actively recommends next steps.`

#### 0:20-0:45 Show the Recommendation Page

Actions:

- open Recommendation page
- show goal board
- show recommendation cards

Say:

`The first visible difference is the recommendation interface. It is now a first-class product surface rather than an implied future module.`

#### 0:45-1:15 Ask for Guidance

Actions:

- ask: `I want to push my personalized AI agent project forward this week.`

Say:

`The new behavior is proactive guidance. Instead of only replying to the question, the system proposes next steps, papers, or task directions.`

#### 1:15-1:40 Show Explanation and Feedback

Actions:

- click a recommendation
- show `why this is recommended`
- click useful or not useful

Say:

`V3 also explains why the recommendation fits this user, based on profile and memory. That explanation makes the mentor behavior more persuasive in a meeting.`

#### 1:40-2:00 Close

Say:

`So V3 turns the memory-aware agent into a guiding agent. The system now helps decide what the user should do next.`

### Acceptance Checklist

- a dedicated recommendation page exists
- recommendation cards are visible
- at least one recommendation includes a rationale
- user feedback controls are visible
- the system makes a proactive suggestion that V2 could not make
- the presenter can clearly state that V3 adds mentoring

## V4 Demo Script

### Version Theme

Action Loop

### Whole-Group Upgrade Line

`Compared with V3, V4 now turns recommendations and intentions into visible executable workflows.`

### Two-Minute Demo Script

#### 0:00-0:20 Opening

`This is V4. The key change is that the system is no longer limited to memory and guidance. It now converts intent into execution.`

#### 0:20-0:45 Show Workflow Studio

Actions:

- open Workflow page
- show workflow studio
- show execution trace area

Say:

`The first visible difference is the execution interface. We now have a workflow view, not just chat and recommendations.`

#### 0:45-1:15 Convert a Suggestion into Action

Actions:

- open a recommendation
- click `create task` or equivalent
- show generated steps

Say:

`The new behavior is action conversion. A recommendation is no longer only advice. It becomes a task with explicit executable steps.`

#### 1:15-1:40 Run and Replay

Actions:

- execute the task
- show the trace
- show replay or retry

Say:

`This is the major jump from V3. The system now exposes how it executes and allows the audience to inspect the process step by step.`

#### 1:40-2:00 Close

Say:

`So V4 upgrades the mentor into an assistant that can actually act. The visible execution trace is the proof of progress.`

### Acceptance Checklist

- a workflow or task studio page exists
- a recommendation can be converted into an action
- execution steps are shown
- execution trace is visible
- replay or retry is visible
- the presenter can clearly state that V4 adds execution

## V5 Demo Script

### Version Theme

Trustworthy Organism

### Whole-Group Upgrade Line

`Compared with V4, V5 now closes the loop with visible alignment, security, and auditability.`

### Two-Minute Demo Script

#### 0:00-0:20 Opening

`This is V5, our trustworthy integrated version. The major difference is that the system now shows not only what it can do, but also how it remains safe, aligned, and auditable.`

#### 0:20-0:45 Show the Trust Interfaces

Actions:

- open system overview
- open Trust Center
- open Security Center
- open Audit Log

Say:

`The first visible difference is governance. Alignment and security are now explicit product interfaces, not hidden backend assumptions.`

#### 0:45-1:15 Run the Full Flow

Actions:

- show profile and memory
- trigger a recommendation
- convert to action
- begin execution

Say:

`The integrated behavior is now complete: profile and memory support recommendation, recommendation becomes action, and action goes through visible control.`

#### 1:15-1:40 Show Risk Intervention

Actions:

- trigger a risky step
- show confirmation, interception, or permission request
- show the resulting audit log entry

Say:

`This is the new upgrade beyond V4. The system does not only act. It can also justify, intercept, and record risky behavior.`

#### 1:40-2:00 Close

Say:

`So V5 is our full Personalized AI Agent story: memory, mentoring, action, alignment, and security working together in one demoable flow.`

### Acceptance Checklist

- a trust or security dashboard exists
- an audit log exists
- at least one risky action can trigger intervention or confirmation
- the intervention result is logged
- the full chain from profile to memory to recommendation to action is visible
- the presenter can clearly state that V5 adds trustworthiness and governance

## Final Sanity Check Before Any Group Meeting

For every version, ask these five questions:

1. Can the audience point to one new screen?
2. Can the audience name one new capability?
3. Can the presenter explain the upgrade in one sentence?
4. Can every member describe one concrete contribution in that version?
5. Can the live demo prove the upgrade without relying on explanation only?
