# Persbot 五版本 Demo Playbook

## 演示总规则

整套展示必须遵守两个原则：

1. 同一套系统，只换启动入口
   也就是只换 `dev:v1` 到 `dev:v5`，不换仓库，不换分支，不换数据故事。
2. 同一个用户故事，逐版扩容
   建议统一使用：
   `我要把 Persbot 搭成一个面向研究与效率场景的 Personalized AI Agent。`

## 推荐演示顺序

### V1

- 启动：`pnpm dev:v1`
- 先看欢迎页上的版本卡片
- 再看左侧菜单只剩基础模块
- 最后演示登录、聊天、Provider、Config

要说的话：

`V1 先把系统收缩成最小可用 Agent，只保留基础聊天和配置闭环。`

### V2

- 启动：`pnpm dev:v2`
- 对比左侧菜单，新增机器人、知识库、Persona
- 点进平台接入页和知识库页

要说的话：

`V2 相比 V1，把接入能力和用户知识能力补齐了。`

### V3

- 启动：`pnpm dev:v3`
- 对比左侧菜单，新增 Extension
- 进入扩展页，展示 Installed / Market / Skills 三个标签

要说的话：

`V3 相比 V2，把系统从固定能力升级成可扩展的插件生态。`

### V4

- 启动：`pnpm dev:v4`
- 对比左侧菜单，新增 Conversation、Session、Cron、SubAgent、Dashboard
- 展示这是一套能运营、能调度、能编排的 Agent 系统

要说的话：

`V4 相比 V3，不只是可扩展，还能真正运行和运营。`

### V5

- 启动：`pnpm dev:v5`
- 对比扩展页，新增 MCP 和 Components
- 对比侧边栏，新增 Console 和 Trace

要说的话：

`V5 相比 V4，把外部工具接入和系统可观测性补齐，形成完整 Persbot。`

## 每版 1 分钟讲法

六个人的讲法统一沿用这条主线：

- Yi Ding 讲认知与规划
- Jinchang Zhu 讲长期记忆
- Chenghao Wu 讲推荐与用户兴趣建模
- Xiaojian Nie 讲视觉工作流与执行
- Ying Liu 讲对齐与行为边界
- Yaxin Li 讲安全、隐私与沙箱

### V1

- 这版先只保留基础 Agent 壳层
- 导师能直接看到系统被裁成最小闭环
- 六个人的可讲点是：规划基线、记忆接口预留、推荐冷启动、工作流隔离、对齐收口、安全边界收口

### V2

- 这版补了机器人接入、知识库和 Persona
- 导师能直接看到系统开始具备“接入用户”和“理解用户”的能力
- 六个人的可讲点是：上下文接入、记忆输入面、兴趣画像、平台接入、导入安全、凭证边界

### V3

- 这版补了插件生态
- 导师能直接看到插件市场、已安装插件和技能页
- 六个人的可讲点是：工具规划、工具偏好记忆、推荐排序、技能封装、插件安全、扩展沙箱

### V4

- 这版补了运营层
- 导师能直接看到会话、调度、多代理和运营看板
- 六个人的可讲点是：任务树扩展、会话记忆沉淀、主动推荐、工作流调度、长链路对齐、运行审计

### V5

- 这版补齐 MCP、组件和观测
- 导师能直接看到最终完整系统
- 六个人的可讲点是：外部工具编排、全链路记忆闭环、跨工具推荐、GUI 到 MCP 的执行桥接、Trace 对齐、最终隐私与沙箱闭环

## 组会防追问建议

- 如果导师问为什么版本差异这么明显：
  直接说这是同一套最终系统按阶段开放模块的展示方案。
- 如果导师问为什么不做五套完全不同的代码：
  直接说为了降低 bug 风险，采用同一代码基座做分阶段开放，更符合工程落地。
- 如果导师问每个人具体做了什么：
  直接打开对应版本文档里的“六人具体工作”章节。
